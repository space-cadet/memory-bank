## Description

Root-cause follow-up to the 2026-09-10 incident in which `mb task create`
regenerated `memory-bank/tasks.md` from an incomplete SQLite projection and
silently overwrote richer Markdown-only entries. The file was restored from
Git; no runtime impact.

Commit `9661832` ("fix: make task registry regeneration explicit") removed the
*acute* hazard by making regeneration opt-in (`--regenerate`). The underlying
cause remains: the SQLite index is an **incomplete projection** of the
Markdown source, because the parsers only recognize a subset of the formats
actually in use.

Consequences if left open:
- Any future `--regenerate` (or a regression of the opt-in guard) still
  produces a gutted `tasks.md`.
- The incompleteness is invisible — nothing surfaces drift between the two
  representations until someone regenerates and notices the loss.

Standing decision (2026-09-10): **Markdown remains the source of truth;
SQLite is a derived query index only.**

## Acceptance Criteria

- [ ] `parse-tasks.js` recognizes all actual task-ID families in use:
      `T<N>`, suffixed (`T28a`, `T35d`), `INFRA-*`, `SEC-*`, `META-*`
- [ ] Date-heading parser handles both `##` and `###` levels uniformly
      across session files and edit chunks
- [ ] Fixture corpus + regression tests for the above (extend
      `mb-cli/test/` conventions; existing suites: `cli.test.js`,
      `event-*.test.js`)
- [ ] Drift detection: a command or report that surfaces divergence between
      SQLite and Markdown (IDs present in one but missing from the other)
- [ ] Regeneration is either merge-preserving or refuses/warns loudly when
      the projection is incomplete
